# Агривольтаика — продукция, энергия, доход

[Размещение: GitHub → Render → Tilda](docs/DEPLOYMENT_RU.md).

Культуры выбираются только из строк с числовой урожайностью: 32 названия в текущем снимке. Температура и осадки загружаются из NASA за выбранные месяцы; ручной ввод сохранён как явная альтернатива. Технические пояснения и названия источников не показываются в сравнении вариантов.

Версия 4 подбирает приближённое множество компромиссных вариантов по трём целям: продуктивность, годовая выработка электроэнергии и NPV дополнительного денежного потока. Пользователь сравнивает показатели и явно выбирает вариант. Автоматического выбора «единственного оптимума» нет.

На сайте энергетическая часть содержит только установленную мощность и годовую выработку. Геометрия, число панелей, исходные коэффициенты и внутренние расчёты хранятся на сервере и доступны в закрытом калькуляторе владельца. Они не входят в публичный JSON, OpenAPI или выгрузку пользователя.

Это предварительное сценарное сравнение. Связь геометрии, микроклимата и биологического отклика реализована, но не прошла полевую валидацию. Средние по строкам базы используются как индивидуальные ориентиры, а не доказанный причинный эффект панелей. Подробности: [методика](docs/METHODOLOGY_RU.md), [аудит](docs/AUDIT_RU.md).

## Запуск сайта

Python 3.11 или 3.12, команды из каталога репозитория:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000/calculator. Начальные числа — пример; ручной ввод погоды позволяет проверить сервис без интернета. Для встраивания в сайт сохранена точка входа `app:app`. Внешнему интерфейсу нужен новый контракт версии 4. При разных доменах задайте `CORS_ORIGINS=https://your-site.example`.

## Закрытая страница владельца

На Render задайте `AGRIVOLTAIC_OWNER_PASSWORD` — собственный пароль не короче 12 символов. После переразвёртывания откройте `https://service-av.onrender.com/owner/`, логин `owner`. Без переменной страница не подключается. Все её страницы и JSON-маршруты требуют авторизацию. Это такая же форма расчёта и сравнения вариантов, дополненная полными конфигурациями каждого варианта. Расчёт выполняется непосредственно на этой странице; журнал не нужен. Закрытые расчёты не записываются в SQLite: для сохранения результата скачайте JSON кнопкой в интерфейсе.

Для локального запуска сохранена команда `python owner_console.py`. Для работы в браузере используйте HTTPS. Пароль задаётся в переменных Render и не включается в код Tilda или репозиторий.

Записи публичного калькулятора сохраняются отдельно. SQLite хранится в `AGRIVOLTAIC_PRIVATE_DIR`, по умолчанию в `private/`. Для сохранности истории между переразвёртываниями нужен постоянный диск либо внешняя БД. Без постоянного хранилища журнал работает, но записи могут потеряться после перезапуска/переразвёртывания. Каталог исключён из Git и поставки. Не публикуйте весь репозиторий как статические файлы.

Закрытые настройки в необязательном `private/policy.json` переопределяют `DEFAULT_POLICY` из `agrivoltaic/optimization.py`. До реального использования замените цены оборудования коммерческими данными и проверьте ограничения конструкции для хозяйства.

## Расчёт

Модуль: 610 Вт, 2382 × 1134 мм, КПД ≈ 22,58%. Выработка рассчитывается через площадь модулей, облучение наклонной поверхности с учётом затенения, КПД и совокупные эксплуатационные потери.

- NSGA-II: недоминируемая сортировка, crowding distance, турнирный отбор, SBX, полиномиальная мутация и элитизм. По умолчанию 32 особи, 16 поколений, seed 42; отображаются до 12 разнесённых вариантов.
- Геометрия влияет на затенение, распределение света, сценарное охлаждение и испарение, продуктивность, мощность, выработку и стоимость конструкции.
- Индивидуальные средние считаются по числовым строкам конкретной культуры/вида. Пшеница: 75,5% контроля по четырём строкам. Повторные строки одной публикации имеют одинаковый вес, поэтому среднее не является метаанализом независимых исследований.
- Для культур база берётся из локального файла FAO: `Yield`, подходящая страна, последний год, проверенные единицы; либо вводится вручную. Для рыбы и древесины файлы содержат общие объёмы без площади, поэтому продуктивность на гектар вводится вручную. Абсолютный выход рыбы из таблицы не означает установленную прибавку от АВ.
- Стоимость капитала: прямая ставка или WACC. Финансовая цель — NPV, учитывающий вложения, стоимость капитала, дополнительный доход, OPEX и деградацию выработки. Отдельно показан прирост денежного потока первого года.
- Полив: сезонный водный баланс, экономия м³ и рублей. Заморозки, засуха, град: раздельные вероятность и тяжесть потерь; вводимые защитные эффекты являются сценарными предельными значениями. По умолчанию риски не монетизируются.
- Каждый показанный вариант проверяется на 3 погодных × 3 экономических сценариях. Число сценариев с неотрицательным NPV не является вероятностью успеха. Проверка устойчивости не заменяет пользовательский выбор и не является отдельной робастной оптимизацией.

## Публичный API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/calculator` | Форма и сравнение вариантов |
| GET | `/products` | Виды из числовых строк базы |
| GET | `/health` | Работоспособность приложения |
| POST | `/calculate` | Подбор, сохранение закрытой записи, публичные показатели |
| GET | `/calculations/{id}` | Показатели и текущий выбор |
| POST | `/calculations/{id}/selection` | Сохранить `variant_id` из этого расчёта |

Пример запроса и публичного ответа: [examples/scenario.json](examples/scenario.json), [examples/result.json](examples/result.json).

```bash
curl -X POST http://127.0.0.1:8000/calculate \
  -H 'Content-Type: application/json' --data-binary @examples/scenario.json
```

Геометрические поля старого API больше не принимаются. Недопустимые/неизвестные поля — 422, недоступность погодного источника — 503, занятость расчётных слотов — 429. Старые публичные диагностические маршруты моделей удалены. Сообщений «модель не обучена» в пользовательском процессе нет.

## Источники и обучение

Три Google Sheets в `data/sources.json` проверены 5 октября 2026: HTTP 200 и 178 строк до отбора. [Протокол источников](docs/source-check.json). Происхождение первоначальных локальных выгрузок FAO/Росстата не подтверждено точными upstream-ссылками. NASA-парсер проверен на фикстурах по документированному формату; живой запрос в этой среде завершался ошибкой TLS. При отказе нет выдуманного погодного fallback.

```bash
python download_data.py
python prepare_dataset_advanced.py
```

Все три источника должны пройти проверку до атомарного переключения снимка `dataset/current.json`. Строки сохраняют URL/идентификатор источника, номер строки и хеш снимка. Автоматическое обновление не переобучает модель.

Исходные ML-модели со случайными признаками исключены из рабочей поставки. Отдельный исследовательский конвейер `agrivoltaic.training` принимает только проверенные наблюдения `reviewed=true`, делит данные по DOI и связанным исследованиям, обучает scaler внутри folds, сравнивает MLP/RF с константным baseline на независимых группах. Шаблоны — `dataset/*reviewed_template.csv`. Этот конвейер пока не подключён к публичной оптимизации: её биологический отклик остаётся явно описанной сценарной зависимостью.

## Структура и проверка

`agrivoltaic/`: `api.py` и `public_schemas.py` — публичный контракт; `optimization.py`, `nsga2.py`, `physical_scenario.py` — поиск и связанные расчёты; `coefficients.py`, `catalogs.py`, `ingestion.py`, `weather.py` — данные; `economics.py`, `agronomy.py` — экономика, вода и риски; `storage.py` — сохранение публичных расчётов; `owner.py` — защищённый калькулятор с полными конфигурациями. `static/` — интерфейс без внешних CDN; `tests/` — проверки; `docs/` — методика и аудит.

```bash
pip install -r requirements-dev.txt
pytest -q
ruff check .
ruff format --check .
```

Тесты проверяют программную реализацию, включая недоминируемость, влияние геометрии и отсутствие утечки конфигурации. Они не подтверждают точность урожайности на реальных полях. Удалённый GitHub и размещённый сервис этой локальной работой не изменены.
